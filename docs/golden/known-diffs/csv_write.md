# Known differences from polars: `write_csv_str`

Data: `docs/golden/csv_write.json` (generated by `scripts/csv_write.py` with
polars 2.1.0, 165 cases). Apart from the items below, the text is byte for byte
what `DataFrame.write_csv()` returns for the same frame and options: the
header, the line terminator on every line (the last one included), the quote
styles, `null_value`, `include_bom`, the number, date and datetime text, and
the shapes (no rows: header only; no columns: one empty line).

## Options that are not available

`write_csv_str` takes seven options: `include_header`, `separator`,
`line_terminator`, `quote_char`, `quote_style`, `null_value`, `include_bom`.
These polars arguments have no counterpart:

- `float_precision`, `float_scientific`, `decimal_comma`: floats are always
  written in the shortest round-trip form (`1.0`, `0.1`, `1e+20`, `1e-6`).
- `date_format`, `datetime_format`, `time_format`: dates are `YYYY-MM-DD` and
  datetimes `YYYY-MM-DDTHH:MM:SS.ffffff`.
- `batch_size`, `compression`, `compression_level`, `check_extension`,
  `storage_options`, `credential_provider`, and the `file` argument: the
  function returns the text (`@plfs.write_csv` writes a file).
- `quote_char=""` (polars: raises `ValueError` on `write_csv`): `quote_char` is a
  `Char`, so it cannot be empty. Use `quote_style=Never` to write no quotes.

## Option checks

polars checks that `separator` and `quote_char` are single bytes and raises
`ValueError` otherwise. It does not check anything else: a separator of
`"\n"` or `"\r"`, a quote character of `"\n"` or `"\r"`, or the same character
for both are accepted, and the output cannot be read back.

`write_csv_str` accepts any single `Char` (so `"é"` and emoji are fine as
separator or quote character) and raises `InvalidOperation` for those
combinations instead of writing unreadable text:

- `separator must not be a line break (LF or CR)`
- `quote_char must not be a line break (LF or CR)`
- `separator and quote_char must differ, got ','`

The golden file keeps these as `"restricted": true` cases that expect
`InvalidOperation` (polars writes some text for them).

## Numbers, booleans and dates that contain the separator

With `quote_style="necessary"` or `"non_numeric"`, polars checks only strings
(and header names) for the separator and the quote character. A number or date
is written raw, so `separator="."` with a float column or `separator="-"` with
negative integers produces rows that cannot be read back. `write_csv_str`
checks every field instead and quotes such a number, boolean, date or datetime
(`"1.5"`). This only matters for separators or quote characters that occur in
numeric text (digits, `-`, `+`, `.`, `:`, `e`, `T`, and the letters of `true`,
`false`, `NaN`, `inf`). `Never` writes everything raw, as polars does. The
golden file contains no case for this.

## `null_value`

As in polars, `null_value` is written as it is: it is not quoted or escaped
under `Necessary`, `NonNumeric` or `Never`, even when it contains the separator
or a quote character. Under `Always` it is wrapped in quote characters
(`"NA"`), also without escaping.

## Dates out of range

polars panics (`out-of-range date`) for a `Date` more than about 96 million
days from 1970-01-01 (the limit of its calendar library). The golden file stays
inside that range. `write_csv_str` formats up to 110 million days, the same
limit as `Series::cast` to `String`, and raises `ComputeError` beyond it:

```
column "d": cannot write Date to CSV: value date(110000001) at index 1 cannot be formatted
```

Every `Datetime` (the whole `Int64` range of microseconds) can be formatted,
for example `-290308-12-21T19:59:05.224192` and `+294247-01-10T04:00:54.775807`.
The check runs before anything is written; with several bad dates the first
column (left to right) and its first row are reported.

## Lone surrogates (`@plfs.write_csv` only)

A MoonBit `String` can hold a lone surrogate (a UTF-16 code unit in the range
U+D800 to U+DFFF with no partner), which has no UTF-8 encoding. `write_csv_str`
returns the text as it is. `@plfs.write_csv` has to encode the text as UTF-8, so
a frame with such a string in a value or a column name raises `ComputeError`
and the file is not touched (it is neither created nor changed). polars strings
are always valid UTF-8, so there is nothing to compare with. Remove or replace
the character before writing the file.

## Files

`@plfs.write_csv` raises `PolarsError::IOError(msg)` when the file cannot be
written (no such directory, no permission); `msg` is the text of the operating
system, with the path, and `e.to_string()` is `IOError: <msg>`.

## Types

The library has no Time, Duration, Decimal, Categorical, Binary, nested or
timezone-aware types, nor integer types other than `Int32` and `Int64`, so
none of the corresponding polars output is covered.
