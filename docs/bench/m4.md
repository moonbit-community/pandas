# M4 benchmarks (CSV)

- Machine: lab5 (Intel Core i9-13900K, 32 threads, 62 GiB RAM, Linux 6.8). The machine is shared:
  the load average was 5 to 7 during the runs, so absolute numbers are somewhat noisy. Compare
  items within this table, not with the tables of `m2.md` or `m3.md`.
- Date: 2026-11-25
- Toolchain: moon 0.1.20261119 (738607b 2026-11-19)
- Tree: measured on the M4 branch, 2026-11-25 (`read_csv_str` and `write_csv_str` with the
  benchmark items of `src/pl/bench_test.mbt`).
- Commands: `moon bench --release --target native -p smallbearrr/pandas/pl -f bench_test.mbt -i 36-43`
  and the same with `--target wasm-gc`, run 3 times in a row (the 7 CSV items are the last 7 tests
  of the file). Every cell is the **median of the three mean times**; the three means follow in
  brackets, in run order. Each mean is the `moon bench` mean of 10 rounds. The builds are release
  builds (`--release`).
- Source: `src/pl/bench_test.mbt` (the "bench csv ..." and "bench write_csv_str ..." items; the
  earlier `csv_read_bench_test.mbt` and `csv_write_bench_test.mbt` of the two tasks were merged into
  it). Every item uses n = 1,000,000 rows and 5 columns; the inputs are built outside the timed
  closure and are deterministic, so runs are reproducible.

## What is measured

**Reading** (`read_csv_str`): the text has the header `i,f,s,b,d` and, for row `i`:

| column | text | distribution |
| --- | --- | --- |
| `i` | `i` | the row number, all values different (1 to 6 digits) |
| `f` | `i % 1000` `.` `i % 97 + 10` | 97 * 1000 combinations repeat, two fractional digits |
| `s` | `str` `i % 1000` | 1 000 distinct strings, none needing quotes |
| `b` | `true` / `false` | alternating |
| `d` | `2024-MM-DD` | `MM = i % 12 + 1`, `DD = i % 28 + 1`: 84 distinct dates |

No field is quoted and no field is empty. The four reading items differ in the options only:

- **inferred, default**: `CsvReadOptions::new()`. The columns come out as `Int64`, `Float64`,
  `String`, `Boolean`, `String` (the date is text without `try_parse_dates`).
- **inferred, `try_parse_dates=true`**: `Int64`, `Float64`, `String`, `Boolean`, `Date`.
- **all `String`**: `infer_schema_length=Some(0)`.
- **overrides**: `schema_overrides` gives all five columns their types (no inference).

**Writing** (`write_csv_str`): a frame of 1,000,000 rows with `i` an `Int64` (`i * 7919 - 1000`),
`f` a `Float64` (`i * 0.37 - 5.0`, mostly long fractional parts), `s` a `String` (every 5th
value is `a,"q"<i>`, which needs quoting and a doubled quote; the others are `value<i>`), `b` a
`Boolean` (`i % 3 == 0`) and `d` a `Date` (`i % 40000` days after 1970). The last item is a single
`String` column of 1,000,000 values that all need quoting (`x,"y" <i> z`).

## Reading the numbers

- Every item is below 1 s on both backends (spec section 7 asks for 1M-row CSV parsing). Reading
  1,000,000 rows of 5 columns costs about a quarter of a second on native and about half a second
  on wasm-gc.
- Reading is one pass over the text (the fields are kept as offsets in flat arrays and turned into
  values column by column), and inference looks at no more than `infer_schema_length` records per
  column, so the inferred and the overridden reads cost the same: the difference between the first
  and the fourth item is within the run-to-run spread. `try_parse_dates=true` costs about the same
  as the default (+4 % on native, -11 % on wasm-gc: inside the spread).
- The all-`String` read is the cheapest on native (no number parsing) and the most expensive on
  wasm-gc (1,000,000 small strings are allocated for each of the 5 columns, and allocation is
  probably what costs on wasm-gc; not measured separately).
- Writing costs about twice as much as reading on native: it formats every value (floats take the
  shortest round-trip digits) into one `StringBuilder`. The cost is linear in the output (one
  quoted column of 1M values: 62 ms; five columns: 592 ms). `quote_style=Always` adds about 5 %.
- wasm-gc is 1.2 to 2.4 times native: about 1.2 times for writing five columns, 1.7 to 2.4 times
  for reading (1.9 default, 1.7 with dates, 1.8 overrides, 2.4 all strings), 2.0 for the one quoted column.
- A later run on the same branch with the machine busier (load average 8) was 0 to 20 % slower on
  native than these medians, so the comparisons above hold.
