## 已知问题修复轮之后

`Series::cast` 改成直接在底层数组上按类型循环构建结果，不再逐元素取 `AnyValue` 再用 `from_any_values` 重建。

- Machine: lab5（测量时负载约 15，其它任务同时在跑，绝对值比上表的 27.61 ms 慢，所以前后对比是同一时段交替跑的）
- Command: `moon bench --target native -p smallbearrr/pandas/pl -f bench_test.mbt`
- 前：M1 合并后的 main（`a0b4c0c`）的 `cast.mbt`，用同一份 `bench_test.mbt`；后：本轮的 `cast.mbt`
- 每项跑 3 次（前、后交替），表里是 3 次均值的中位数，括号里是 3 次的值（n = 1,000,000 行）

| Item | 前 | 后 |
| --- | --- | --- |
| `Series::cast` i64 -> f64 | 29.08 ms (29.08 / 28.64 / 29.82) | 5.98 ms (9.04 / 5.98 / 5.25) |
| `Series::cast` f64 -> i32（10% null） | 30.48 ms (30.48 / 29.07 / 33.04) | 9.15 ms (12.26 / 7.03 / 9.15) |
| `Series::cast` i64 -> str | 61.56 ms (61.56 / 76.96 / 59.75) | 44.69 ms (48.96 / 39.29 / 44.69) |
| `Series::cast` str -> f64 | 170.47 ms (151.05 / 189.42 / 170.47) | 144.01 ms (260.71 / 139.12 / 144.01) |

i64 -> f64 和 f64 -> i32 不再为每个元素分配 `AnyValue`，快了约 5 倍和 3 倍。转字符串和字符串转数字的时间主要花在格式化和解析本身，收益较小。后三项是本轮新增的基准（`bench_test.mbt`）。
